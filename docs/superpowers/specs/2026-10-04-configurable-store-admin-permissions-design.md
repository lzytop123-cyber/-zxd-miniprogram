# 店长模块权限可配置设计

日期：2026-10-04  
状态：待评审  
前置：[后台总部 / 店长角色设计](2026-10-04-admin-store-roles-design.md)

## 目标

总部可为**每个店长账号**勾选可见/可操作的后台模块：

- 新建店长时，**本店经营模块默认全开**（与现网标准店长一致）
- **全部模块均可勾选**（含原「仅总部」模块）
- 有门店维度的数据**仍锁本店**；无门店维度的配置模块勾选后按全站读写，并在 UI 标明「全站配置」

总部账号不受 `permissions` 限制，始终全开。

## 非目标

- 角色模板 / 店员角色（可后续叠加）
- 字段级权限、审批流
- 独立权限审计页（沿用现有操作日志即可）
- 一人多店

## 数据

`admin_users` 新增：

- `permissions`：JSON 字符串数组，如 `["dashboard","receipts",…]`
  - `null` / 缺列：店长视为「标准本店模块全开」（兼容旧数据）
  - `[]`：店长无任何模块（仅可登录看空壳/改自己密码若已有入口）
  - 总部账号该字段忽略，可为 `null`

迁移：现有 `role=store` 账号写入本店默认模块全集；`role=hq` 保持 `null`。

## 模块清单

每个 key 对应菜单路径与一组 API 前缀（实现时维护一张映射表）。

### 本店默认集（新建店长默认勾选）

| key | 菜单 | 数据范围 |
|---|---|---|
| `dashboard` | 数据总览 | 本店 |
| `receipts` | 收款管理 | 本店关联收款 |
| `live_board` | 实时占座 | 本店 |
| `stores` | 门店资料 | 仅本店；**禁止新建门店** |
| `calendar` | 营业日历 | 本店 |
| `pricing` | 价格 | 本店；**禁止跨店复制** |
| `seats` | 座位 | 本店 |
| `reservations` | 预约订单 | 本店 |
| `locks` | 门锁 | 本店 |
| `door_logs` | 开门记录 | 本店 |
| `card_orders` | 套餐购买 | 本店 |
| `period_cards` | 期限卡 | 本店 |
| `deal_mappings` | 团购映射 | 本店 |
| `exchange` | 兑换记录 | 本店 |

### 扩展集（新建默认不勾；均可勾）

| key | 菜单 | 数据范围 |
|---|---|---|
| `admins` | 管理员 | 仅 `role=store` 且 `store_id=本店`；不能创建/改总部账号 |
| `pay_accounts` | 收款账户 | **只读**本店已绑定账户；不能新建/改全局账户配置 |
| `users` | 用户 | 仅在本店有过预约/购卡/核销的用户 |
| `wallet_logs` | 钱包流水 | 同上用户集合 |
| `point_logs` | 积分流水 | 同上用户集合 |
| `invites` | 邀请 | 同上用户集合（邀请人/被邀请人落在本店用户集） |
| `coupons` | 优惠券 | 同上用户集合 |
| `banners` | Banner | 全站配置（UI 标注） |
| `announcements` | 公告 | 全站配置 |
| `notifications` | 消息 | 可发；若带 `store_id` 则只能发本店或未指定时默认本店 |
| `contact` | 联系店长 | 全站配置 |
| `booking_setting` | 预约规则 | 全站配置 |
| `study` | 学习数据 / 助手用量 | 全站配置（无店维度时） |
| `knowledge` | 知识库 | 全站配置 |
| `wrongbook` | 错题本后台 | 全站配置 |
| `market` | 上岸集市 | 全站配置 |
| `system` | 系统状态 | 全站配置 |
| `operation_logs` | 操作日志 | 仅本店相关操作（`target` 含本店或操作者为本店账号） |

「恢复标准店长」= 权限重置为本店默认集（去掉全部扩展集）。

## 鉴权

1. **菜单 / 前端路由**：`canAccessPath` 改为查模块映射；无对应权限则隐藏并拦路由。
2. **API**：扩展现有 `AdminRoleGuardMiddleware`：
   - 总部：放行
   - 店长：路径 → 模块 key；不在 `permissions` 内 → 403
   - 仍保留 `scope_store_id` / `assert_store_access` 做数据隔离
3. **登录与 `/admin/me`**：返回 `permissions: string[]`（总部可返回全部 key 或省略表示全开）。
4. **硬限制（即使用户勾了也不放开）**：
   - 店长 `POST /api/admin/stores`（新建门店）始终 403
   - 店长价格跨店复制始终 403
   - 店长不能把账号改成 `role=hq`，不能改其他门店店长
   - `pay_accounts` 写接口对店长始终 403（只读本店绑定）

## 后台 UI

「管理员」创建/编辑：

- 角色选「店长」时展示两组勾选：本店模块 / 扩展模块
- 默认：本店全选、扩展不选
- 提供「恢复标准店长」按钮
- 列表可用标签摘要权限数量（如「标准」或「标准+3」），不必展开全部

## 验收

1. 新建店长不改勾选 → 行为与现网标准店长一致  
2. 去掉 `receipts` → 菜单无收款，直接打收款 API → 403  
3. 勾上 `users` → 只能看到本店关联用户，看不到其他店纯用户  
4. 勾上 `admins` → 可为本店再建店长；不能建总部号、不能改别店店长  
5. 勾上 `banners` → 可编辑全站 Banner，页上有「全站配置」提示  
6. 总部账号行为不变  

## 测试

- 单元：权限解析（null / 默认集 / 自定义）、路径→模块映射、硬限制  
- API：店长有/无某模块的 200/403；用户列表本店过滤  
- 前端：店长 session 带 permissions 时菜单过滤
