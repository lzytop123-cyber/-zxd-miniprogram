# 收款管理实施计划

**Goal:** 在现有后台记录四个渠道的收款和已完成退款，展示月度、年度和渠道净收款。

**Architecture:** 独立收款、退款表，复用管理员鉴权和审计。小程序微信支付按订单唯一键同步；余额消费、团购核销不作为新增收款。金额使用 Decimal，退款用条件更新防止累计超额。

**Tech Stack:** FastAPI、SQLAlchemy、Vue 3、Element Plus。

**Spec:** 本任务对话已确认的“收款概览 + 收款记录 + 关联退款”。

## 约束

- 美团、抖音、微信转账手工登记实际收款，微信支付同步预约、购卡、充值成功订单。
- 收款和退款各按自己的北京时间日期归属月份；不推断历史支付日期。
- 退款操作只记账，不调用支付退款、不更改钱包或卡权益。
- 本地实现和测试，不修改真实业务数据，不部署。

## 验证数据

同一请求重试只产生一行；剩余可退 70 元时申请 70.01 元应拒绝且不改变汇总。
重复同步同一微信订单不得新增收款；旧购卡/预约缺支付日期时不计入月年汇总，补日期后计入。
